# C01 mutation retry safety

Updated 22 October 2026. C01 is still incomplete. These checks cover SDK transport behavior, not a v2 backend deployment or a cloud acceptance run.

## Change

`UnknownOutcomeError.idempotencyKey` and `V2ApiError.idempotencyKey` now retain the key actually sent with a mutation. This includes keys generated by the SDK. A caller can recover that key after a lost response instead of accidentally creating a second intent.

The SDK validates explicit and generated keys before sending. It never retries automatically. A failed read does not produce an unknown-mutation error.

A successful HTTP status does not guarantee that the client received a usable result. Interrupted response streams, invalid JSON and schema-invalid success bodies now produce `UnknownOutcomeError` for mutations, with the original cause and key. Reconcile the outcome or explicitly retry the original payload with that key. Do not create a new key for the same intent.

## Caller obligations

Persist the key and original payload before sending any booking, payment or custody command. Error recovery alone cannot preserve a key after process death. Supply the persisted key through `V2MutatingOpts.idempotencyKey`. An intentional payload change starts a new intent with a new key.

The server must still enforce actor-scoped key and payload matching, durable business uniqueness and aggregate versions. SDK tests do not prove those backend guarantees.

## Remaining C01 gates

The earlier freeze announcement was premature. Keep feature dispatch blocked until these requirements have current evidence:

- Every registry operation resolves to real request and response schemas, a matching SDK method, a permission rule and a deterministic fixture.
- Replace permissive response placeholders in the v2 SDK. Align SDK paths with the registry.
- Publish OpenAPI, executable transition guards and transaction, audit, idempotency and outbox integration boundaries.
- Publish v2 fixtures, legacy compatibility checks and consumer compile cases that actually exercise v2 interfaces.
- Revalidate the complete freeze on a pinned revision. Hash contracts, SDK and fixtures together, not just `packages/contracts`.
- Complete the fresh-cloud environment checks required by P01. Local PostgreSQL checks do not satisfy them.
