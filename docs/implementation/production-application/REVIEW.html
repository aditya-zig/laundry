One application.
Four services. Cloud-only delivery.

A complete customer Android app, delivery Android app and operations console. Agents work in isolated cloud jobs against one frozen contract. One coordinator integrates their pushed branches.

Read the full implementation document ↗

What the build must deliver

Customer

Browse all four services, book kg or piece quantities, approve measured adjustments, track custody, pay at return and review delivered work.

Delivery

Assigned jobs, sealed-container custody, private proof, honest location and durable offline evidence with pending-sync status.

Operations

Intake, consent, care, QC, assignment, cash reconciliation, incidents and audited commercial configuration.

How the apps reach the backend

Target architecture. P00 first reconciles the published garment and kilogram implementations; C01 then freezes additive v2 contracts and preserves historical v1 behavior.

The dispatch sequence

  1. Establish the baseline: P00 and R01 can start independently.
  2. Freeze the foundations: prove cloud runtime, contracts and shared design. Coordinator serializes shared-file changes.
  3. Build in parallel: ten backend feature owners plus the app foundation; then four disjoint screen owners.
  4. Prove the integrated candidate: PostgreSQL/browser acceptance and real Android cloud verification.
  5. Prepare launch: restore rehearsal, business/provider approval and actual fulfillment-pilot evidence.

Start dependencies are a DAG. Runtime peers can be developed concurrently using frozen fake ports; final acceptance uses their real implementations.
